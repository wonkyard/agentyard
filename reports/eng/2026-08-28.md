## Fix choice — why option 2, not option 1

The brief offered: (1) caret-escape every cmd.exe metacharacter, (2) resolve
the shim and spawn the real exe with no shell, (3) require an explicit
executable path.

Chose **(2), with (3) as the refusal fallback.** Getting cmd.exe escaping
provably correct is exactly what Rust / Node / Python all shipped CVEs for —
`"` must reach cmd.exe literally (so metacharacters stay inert) yet be a quote
to the child's parser, which forces simulating cmd.exe's own quote-state machine
to know where to insert `^`. That is a security property riding on a fragile
heuristic. Option 2 removes cmd.exe from the picture: `spawn(realExe, argv,
{shell:false})` passes the prompt verbatim through `CreateProcess` — nothing to
inject into, and `%VAR%` can't expand. The shim-parse is simple, spec'd string
handling, fully unit-tested, and covers npm/pnpm/yarn/bun. The one real
`claude.cmd` on this machine (npm, forwards to a bundled `claude.exe`) resolves
cleanly. Anything unrecognised is refused with a clear action rather than run
unsafely.
